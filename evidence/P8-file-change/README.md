# P-8 — File Change Detection Evidence

## Scenario

P-8 tested rapid file-change activity in the isolated SOC lab.

The scenario simulated ransomware-like file changes using controlled test files to verify whether repeated file activity could be detected and investigated in Splunk.

---

## Detection Source

The primary Windows telemetry used for this scenario was:

```text
Windows Security Event ID 4663
```

Event ID `4663` provides object-access activity that can be used to investigate file-system events.

---

## Detection Logic

The detection identifies:

- At least 5 file events
- At least 2 unique files
- Activity within a 1-minute window
- Files matching the `P8-Test` pattern

---

## SPL Detection Query

```spl
index=wineventlogs EventCode=4663
| search Object_Name="*P8-Test*"
| bin _time span=1m
| stats count as file_events dc(Object_Name) as unique_files by _time host Account_Name
| where file_events>=5 AND unique_files>=2
```

---

## How the Detection Works

### Step 1 — Search File Events

```spl
index=wineventlogs EventCode=4663
```

Searches for Windows Security Event ID `4663`.

### Step 2 — Filter Test Files

```spl
| search Object_Name="*P8-Test*"
```

Filters the results for the controlled P-8 test-file pattern.

### Step 3 — Group Events

```spl
| bin _time span=1m
```

Groups events into one-minute time windows.

### Step 4 — Count Events and Files

```spl
| stats count as file_events dc(Object_Name) as unique_files by _time host Account_Name
```

Counts the total file events and the number of unique files for each time window, host, and account.

### Step 5 — Apply Threshold

```spl
| where file_events>=5 AND unique_files>=2
```

Returns activity when both detection conditions are satisfied.

## Lab Activity

During P-8, rapid file changes were intentionally generated against controlled test files.

The purpose was to create a detectable pattern of repeated file-system activity for SOC monitoring and investigation.

---

## Detection Result

The Splunk search was designed to identify repeated file activity involving multiple test files within a short time window.

The resulting events could be reviewed by the analyst for further investigation.

---

## Investigation

The analyst should review:

- Event timestamp
- Host
- User account
- Number of file events
- Number of unique files
- Affected file names
- Available process information
- Related activity before and after the file events

---

## Detection Threshold

| Detection Element | Threshold |
|---|---:|
| File events | 5 or more |
| Unique files | 2 or more |
| Time window | 1 minute |
| Event ID | 4663 |
| File pattern | `P8-Test` |

## Security Significance

Rapid file activity involving multiple files can be an investigation indicator in some security incidents.

However, similar activity can also be generated by legitimate applications, backups, software updates, or administrative operations.

Therefore, the analyst should correlate the file activity with the host, user, process information, file names, and surrounding telemetry.
